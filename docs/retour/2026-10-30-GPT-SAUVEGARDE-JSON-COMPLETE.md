# Sauvegarde JSON complète — Codex, 30 octobre 2026

Anomalie vérifiée pendant la reprise de l'administration : `core.sauvegarde.CONTENU` ne contenait que auth/group/user, authtoken, core, commercial et comptabilite, alors que `restaurer` faisait un flush de toutes les applications. Un dossier Transport comportant billets, colis, garage, personnel ou échanges pouvait donc perdre ces données après restauration d'un JSON pourtant produit par le logiciel. Les sauvegardes natives SQLite et SQL Server ne sont pas concernées par cette omission.

Le nouveau JSON version 2 inclut toutes les applications métier installées du projet, les utilisateurs/groupes et jetons, les échanges et la licence. Les sessions de navigation ne sont pas transportées ; une reconnexion est nécessaire. L'en-tête déclare le périmètre, le nombre d'objets et leur empreinte SHA-256 ; la lecture refuse les modèles extérieurs et vérifie la présence d'un administrateur avant le vidage transactionnel. L'empreinte contrôle l'intégrité du contenu, ce n'est pas une signature d'origine. Le cache de licence est invalidé après restauration.

Les signaux d'échanges ignorent les sauvegardes rechargées en mode raw : les événements sont eux-mêmes restaurés, pas republiés comme de nouvelles pièces. Après restauration à l'écran, la session courante est fermée avant journalisation ; le compte qui a demandé l'opération peut ne pas exister dans le fichier restauré. Son nom est conservé dans le détail de l'événement. Dans le programme compilé, une sauvegarde native doit réussir avant ce remplacement.

Une archive JSON version 1, partielle ou de périmètre inconnu est refusée avant toute écriture. Elle doit être conservée pour une reprise encadrée dans un dossier séparé ; elle n'est ni effacée ni prétendue complète. L'ancien fichier incomplet ne permet pas de reconstituer des billets ou colis qui n'y ont jamais été exportés.

Six tests de régression sont ajoutés : export/restauration réels de billets, colis, écritures, salariés, événements d'agence et code d'installation protégé ; refus d'un ancien JSON partiel, d'un contenu tronqué/modèle extérieur et d'un champ altéré ; restauration par un administrateur absent du fichier ; sauvegarde native en échec avant remplacement. Suite complète et compilation Windows à citer après la CI. Aucune restauration ni aucun export de données réelles exécuté ; tous les essais utilisent les données fictives et bases de test. L'export complet JSON est confidentiel et distinct d'un dossier fictif .erpsim nettoyé pour partage.
