ERP OHADA : installation sur votre ordinateur Windows
====================================================

Tout est dans ce dossier : le logiciel, Python et les composants.
Il n'y a rien à télécharger et aucune connexion Internet n'est nécessaire.

Il faut Windows 10 ou 11 en 64 bits.
Pour la base SQL Server (facultatif), il faut SQL Server 2017 ou plus récent.


1. PREMIÈRE INSTALLATION (une seule fois)
------------------------------------------

1. Décompressez le zip dans un dossier simple, par exemple C:\ERP-OHADA.
   Clic droit sur le zip > « Extraire tout… ».
   Ne lancez rien depuis l'intérieur du zip.

2. Double-cliquez sur 1-INSTALLER.bat.
   Si Windows affiche « Windows a protégé votre ordinateur », cliquez sur
   « Informations complémentaires » puis « Exécuter quand même ».

3. Répondez aux questions :

   - Base de données :
       1 = SQLite : un simple fichier, rien à configurer.
           C'est le choix conseillé pour un premier essai.
       2 = SQL Server : sur votre serveur SQL déjà installé (voir partie 3).

   - Données de démonstration : clients, articles et pièces fictifs pour
     essayer. Répondez N pour partir d'un dossier vide.

   - TVA : par défaut, AUCUNE TVA n'est appliquée. Répondez O seulement si
     la société facture la TVA (les taux du Cameroun sont alors créés).
     Modifiable ensuite dans Fichier > Paramètres de la société
     (« Configuration de la TVA »).

   - Vente en gros et au détail : pour ne pas ouvrir les cartons dans les
     magasins de gros, vous pouvez réserver la vente au détail à une ou deux
     boutiques. Les magasins les approvisionnent par transfert. Donnez le
     nom de vos boutiques. Ce réglage reste modifiable ensuite dans
     Fichier > Paramètres de la société.

   - Compte administrateur : choisissez votre identifiant et votre mot de
     passe. Notez-les.

4. À la fin, le message « Installation terminée » s'affiche.


2. UTILISER LE LOGICIEL (chaque jour)
--------------------------------------

Double-cliquez sur 2-DEMARRER-ERP.bat.
Le navigateur s'ouvre sur http://127.0.0.1:8000.
Connectez-vous avec le compte créé à l'installation.

Gardez la fenêtre noire ouverte pendant l'utilisation.
Fermez-la pour arrêter le logiciel.

Si la page ne s'ouvre pas tout de suite, actualisez-la (touche F5) après
quelques secondes.


2 bis. PLUSIEURS ORDINATEURS EN RÉSEAU LOCAL (un serveur, des postes)
--------------------------------------------------------------------

Dans l'agence, UN ordinateur est le serveur : le logiciel et la base y
sont installés. Les autres ordinateurs sont des postes utilisateurs.
Ils n'installent rien et utilisent le logiciel dans leur navigateur
(Edge, Chrome, Firefox), chacun avec son propre compte.
Le réseau local suffit : Internet n'est pas nécessaire. La
synchronisation avec la direction est une autre fonction, prévue plus
tard.

Sur le SERVEUR (une seule machine) :
  1. Installez avec 1-INSTALLER.bat (voir partie 1).
     Pour plus de 3 ou 4 postes, préférez SQL Server à SQLite.
  2. La première fois, faites un clic droit sur
     4-DEMARRER-SERVEUR-RESEAU.bat > « Exécuter en tant
     qu'administrateur ». Cela ouvre le pare-feu Windows (port 8000).
     Les fois suivantes, un double-clic suffit.
  3. La fenêtre affiche l'adresse à utiliser sur les autres postes,
     par exemple http://SERVEUR-AGENCE:8000 ou http://192.168.1.10:8000.
     Elle crée aussi le raccourci « ERP OHADA (poste utilisateur).url ».
  4. Facultatif : 5-DEMARRAGE-AUTOMATIQUE-SERVEUR.bat fait démarrer le
     serveur tout seul à chaque ouverture de session Windows. Relancez-le
     pour annuler.
  5. Le serveur doit rester allumé pendant les heures de travail. Fermer
     sa fenêtre noire arrête le logiciel pour TOUS les postes.
  Conseil : faites donner au serveur une adresse IP fixe (réglage de la
  box ou du routeur), pour que l'adresse ne change pas.

Sur chaque POSTE UTILISATEUR :
  - Copiez le raccourci « ERP OHADA (poste utilisateur).url » sur le
    bureau (clé USB ou dossier partagé), ou tapez l'adresse du serveur
    dans le navigateur.
  - Connectez-vous avec le compte de l'utilisateur. L'administrateur crée
    les comptes et leurs droits dans Fichier > Autorisations d'accès.

Si un poste n'arrive pas à se connecter :
  - Vérifiez que la fenêtre du serveur est ouverte ;
  - que le poste et le serveur sont sur le même réseau ;
  - que le pare-feu du serveur autorise le port 8000 (étape 2).


3. UTILISER SQL SERVER
-----------------------

IMPORTANT : l'ERP crée et utilise SA PROPRE base, par exemple ERP_OHADA.
Ne donnez JAMAIS le nom d'une base Sage. Le programme d'installation
refuse d'ailleurs une base existante qui contient d'autres tables que
celles de l'ERP. Vos dossiers Sage ne sont ni lus ni modifiés.

Pendant l'installation, choisissez 2 puis indiquez :

  - Serveur SQL : le nom affiché dans SQL Server Management Studio à la
    connexion. Exemples : localhost   .\SQLEXPRESS   MONPC\SAGE100

  - Nom de la nouvelle base : ERP_OHADA (proposé par défaut).
    Elle est créée automatiquement.

  - Authentification Windows (O) : votre compte Windows doit avoir le droit
    de créer une base sur ce serveur (c'est le cas de l'administrateur
    du PC en général).
    Sinon, répondez N et donnez un compte SQL, par exemple sa, avec son
    mot de passe.

Pilote : si le pilote « ODBC Driver 17 » ou « 18 for SQL Server » de
Microsoft est installé, il est utilisé. Sinon, le logiciel utilise le pilote
Microsoft fourni dans ce dossier : il n'y a rien à installer.

Pour passer de SQLite à SQL Server (ou l'inverse), lancez
3-CHANGER-DE-BASE.bat. L'ancienne base n'est pas effacée.

Reprendre un dossier Sage existant (transition, puis bascule) :
  - Dans l'ERP : Fichier > Reprise d'un dossier existant (administrateur).
    Choisissez 1. le serveur (ordinateur), 2. l'instance SQL (bouton loupe :
    instances détectées, ex. SAGE100 ; vide = instance par défaut), puis
    3. la base de données du dossier (bouton « Lister les bases » : chaque
    base est présentée avec le nom de sa société).
    La base Sage est seulement LUE (aucune écriture). Simulez d'abord,
    puis tapez SYNCHRONISER : l'ERP devient une copie synchronisée, en
    consultation ; la saisie continue dans Sage.
  - Synchronisez aussi souvent que voulu (bouton, ou automatiquement avec
    6-SYNCHRONISATION-AUTOMATIQUE.bat : toutes les heures, sur le même
    serveur, la même instance et la même base ; avec un compte SQL, mettez
    SYNCHRO_UTILISATEUR et SYNCHRO_MOT_DE_PASSE dans logiciel\.env ;
    utilisez de préférence un compte SQL en lecture seule).
    Si la détection ne trouve pas l'instance : démarrez le service
    « SQL Server Browser » sur le serveur, ou tapez le nom de l'instance.
  - Le jour de la bascule : arrêtez la saisie dans Sage, synchronisez une
    dernière fois, vérifiez le rapport, puis tapez BASCULER. L'ERP devient
    le seul logiciel de saisie ; la synchronisation s'arrête.


4. EN CAS DE PROBLÈME
----------------------

- Pour réparer, relancez 1-INSTALLER.bat. Il ne détruit rien : la
  configuration, la base et les comptes sont conservés.

- « Login failed » ou « Cannot open server » :
    vérifiez le nom du serveur et que le service SQL Server est démarré
    (Services Windows > SQL Server (NOM)) ;
    avec un compte SQL, vérifiez que l'authentification « SQL Server et
    Windows » est activée sur le serveur.

- « Port 8000 déjà utilisé » : une autre fenêtre de l'ERP est déjà
  ouverte. Fermez-la.

- Sauvegarde de vos saisies : dans le logiciel, Fichier > Sauvegarde et
  restauration. Avec SQL Server, vous pouvez aussi sauvegarder la base
  ERP_OHADA depuis Management Studio.

- La configuration se trouve dans logiciel\.env (fichier texte).
  Ne le partagez pas : il contient la clé secrète du logiciel et, le cas
  échéant, le mot de passe SQL.
