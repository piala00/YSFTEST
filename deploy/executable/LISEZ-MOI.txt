ERP OHADA - PROGRAMME COMPILÉ (.exe)
=====================================

1. DÉMARRER
-----------
Double-cliquez sur ERP-OHADA-<Édition>.exe. Tout démarre dans la même fenêtre :
  - le serveur du logiciel, ouvert aux autres postes du réseau local
    (ils ouvrent l'adresse affichée dans leur navigateur, rien à installer) ;
  - les sauvegardes automatiques de la base ;
  - la copie miroir vers SQL Server, si elle est réglée (paragraphe 4) ;
  - la synchronisation du dossier d'origine pendant la transition, si elle a été
    commencée à l'écran (Fichier > Reprise d'un dossier existant) ;
  - les échanges direction / agences par la boîte aux lettres, si elle est
    réglée (paragraphe 5) ;
  - le serveur de simulation (port suivant), si une simulation a été créée.
Gardez la fenêtre ouverte ; la fermer arrête tout.
Un second double-clic ne lance pas un second serveur : il ouvre le navigateur.

Premier démarrage : la base SQLite est créée automatiquement, avec le plan
comptable à 7 chiffres, les journaux et l'exercice ; le programme demande
ensuite l'identifiant et le mot de passe de l'administrateur.

2. OÙ SONT LES DONNÉES
----------------------
PAS dans le dossier du programme : on peut le remplacer (nouvelle version) ou
l'effacer sans rien perdre. Emplacement :
    C:\ProgramData\ERP-OHADA\<Édition>
        configuration.env   réglages (clé secrète, base, sauvegardes, miroir)
        erp.sqlite3         la base
        sauvegardes\        sauvegardes automatiques (lecture seule)
        journal.txt         compte rendu des sauvegardes, copies miroir, erreurs
Pour l'afficher :  ERP-OHADA-<Édition>.exe dossier
Autre emplacement : variable d'environnement ERP_DONNEES (ex. D:\ERP-DONNEES).

3. PROTECTION CONTRE UN EFFACEMENT PAR INADVERTANCE
---------------------------------------------------
- Pendant que le logiciel tourne, Windows refuse d'effacer la base (fichier ouvert).
- Sauvegarde au démarrage puis toutes les 4 heures (ERP_SAUVEGARDE_HEURES),
  60 gardées (ERP_SAUVEGARDE_GARDER), en lecture seule, chacune contrôlée.
- Recommandé : une seconde copie sur un autre disque, une clé USB ou un NAS.
  Dans configuration.env :  ERP_SAUVEGARDE_COPIE=E:\Sauvegardes-ERP
- Si la base a disparu, le programme ne recrée PAS une base vide : il le signale
  et propose de remettre la dernière sauvegarde.
- Remettre une sauvegarde (logiciel arrêté) :
      ERP-OHADA-<Édition>.exe restaurer               la plus récente
      ERP-OHADA-<Édition>.exe restaurer <fichier>     une sauvegarde précise
  La base remplacée est mise de côté (erp-avant-restauration-<date>.sqlite3).
- Sauvegarde immédiate :  ERP-OHADA-<Édition>.exe sauvegarder

4. SQLITE + COPIE MIROIR SQL SERVER
-----------------------------------
La société travaille sur SQLite (rapide, hors ligne). Une copie complète est
reportée automatiquement dans une base SQL Server, à chaque intervalle.
Dans configuration.env, retirez le # devant :
    MIROIR_DB_ENGINE=mssql
    MIROIR_DB_HOST=SERVEUR\INSTANCE
    MIROIR_DB_NAME=ERP_MIROIR          (créée si elle n'existe pas)
    MIROIR_DB_USER=                    (vide : compte Windows)
    MIROIR_DB_PASSWORD=
    MIROIR_DB_PYTHON_DRIVER=mssql_python
    MIROIR_INTERVALLE_MINUTES=60
- Sens unique : SQLite -> SQL Server. On n'écrit jamais dans SQL Server pour le
  reprendre ensuite ; la base SQL Server sert aux consultations, aux outils de
  reporting et de secours.
- Tout ou rien, puis contrôle table par table (nombre de lignes identique).
- Refus d'une base SQL Server qui contient d'autres tables que celles de l'ERP
  (une base d'un autre logiciel n'est jamais touchée).
- Copie à la demande :  ERP-OHADA-<Édition>.exe manage miroir

Travailler directement sur SQL Server (sans SQLite) reste possible :
DB_ENGINE=mssql, DB_HOST, DB_NAME, DB_USER, DB_PASSWORD, DB_PYTHON_DRIVER=mssql_python.

5. DIRECTION ET AGENCES : ÉCHANGES AUTOMATIQUES
-----------------------------------------------
Dès qu'Internet est là, chaque serveur dépose les lots destinés aux autres sites
dans une boîte aux lettres et retire les siens (toutes les 5 minutes). Les lots
sont signés et chiffrés : la boîte ne peut pas les lire. Les fichiers .erpx
(écran Échanges) restent le secours. Dans configuration.env :

    ECHANGES_RELAIS_URL=https://relais.exemple.com    (relais Internet)
    ECHANGES_RELAIS_JETON=jeton donné par la direction
ou
    ECHANGES_DOSSIER_PARTAGE=\\SERVEUR\Echanges-ERP     (dossier partagé)
    ECHANGES_INTERVALLE_MINUTES=5

Écran Échanges : « Synchroniser maintenant ». Détails : docs\ECHANGES_AGENCES.md

6. AUTRES COMMANDES
-------------------
    ERP-OHADA-<Édition>.exe local             ce poste seulement (pas de réseau)
    ERP-OHADA-<Édition>.exe simulation 3      simulation fictive de 3 mois dès 09/2026 (dossier séparé)
    ERP-OHADA-<Édition>.exe simulation 2026-01    de janvier 2026 jusqu'à aujourd'hui
    ERP-OHADA-<Édition>.exe simulation 2026-01 6  six mois à partir de janvier 2026
    ERP-OHADA-<Édition>.exe demarrage-auto    démarrer à l'ouverture de session Windows
                                              (relancer pour retirer)
    ERP-OHADA-<Édition>.exe manage <commande> administration (echanges, longueur_comptes…)
Accès réseau désactivé : ERP_RESEAU=0 dans configuration.env.

La documentation du logiciel est dans le dossier « documentation ».
